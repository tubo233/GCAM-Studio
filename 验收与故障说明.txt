GCAM-China Studio 0.1.1 修复与验收说明
日期：2026-11-17

一、这次截图表示什么

GCAM 已成功启动、解析模型并进入计算；最后一行 Period 12: 2055 表示程序开始计算 2055 年。
“Unsolved Part 2: Unsolvable Markets Not Cleared”表示此前存在没有出清的市场，不能把该次结果当作完整、可信的情景结果。该行本身不能证明进程已退出，也不能仅凭截图确定是哪个 CSV 改动导致。

代码中确认的主要诱因是旧版“快速试跑（低精度）”：它把求解器 max-iterations 改成 3，放宽求解和校准阈值。这会显著增加不收敛风险。新版快速验证保留模型的标准求解器，只计算至 2025 年或用户指定的更早年份。

二、已修复的运行问题

1. 成功判定同时要求：进程退出码为 0、最终所有期求解成功、没有未收敛期或校准警告、有有效 BaseX 文件。失败、取消及 R 构建失败保留历史和错误原因。
2. 每次运行使用独立配置、数据库和日志，禁止同一模型并行求解，避免旧日志或共享输出混入本次结果。应用异常退出后，下次启动标记未完成任务。
3. 输入内容签名判断 XML 是否过期；修改、删除、恢复 CSV 覆盖或切换模型后都会正确重新构建。情景组件 XML 覆盖会进入实际配置。
4. R 构建中的硬链接写入改为替换独立文件，防止意外修改基线。跨盘去重失败保留原 XML。复制 Profile 不继承旧构建和旧运行绝对路径。
5. 修复 Windows R locale 导致已安装包被误判缺失的问题；校验 Java 21、64 位 JVM、R 及必需包。模型或数据中文路径使用经过核验的 ASCII 盘符映射。
6. 子进程超时和取消会结束本次进程树；关闭桌面程序结束其后台任务。排队及运行期间锁定相关输入和关键环境设置。
7. 日志按稳定序号重连，缓冲区截断不再丢失后续日志；末尾没有换行的输出也能记录。

三、已修复的编辑与结果问题

1. XML 编辑器及 worker 本地打包，离线可编辑；保存前验证 XML。自定义政策可以立即出现在列表和运行配置中。
2. CSV/XML 切换文件或 Profile 时清除旧数据，忽略迟到响应；保存绑定读取时的 Profile、文件和行号。回车加失焦只保存一次。
3. CSV 正确处理 gzip、合法 NA 缺失标记，拒绝 NaN/Infinity 写入，限制路径越界。
4. Java 查询失败不会复用旧 CSV，每次查询输出独立。空结果和失败运行不会被当作正常导出。
5. 重要：部分年份运行的 BaseX 也可能包含未来初始化值。新版按实际求解年份裁剪查询 CSV，避免把未求解的 2035、2050 等数据导出为情景结果。
6. 修复 2100 年字段遗漏；图表、跨运行比较和数据编辑均能识别 2100 年。结果页优先选择成功运行，并避免异步旧响应覆盖当前选择。

五、给同事的更新和运行方法

1. 退出旧程序。备份原 GCAM-Studio\data，保留同事自己的 GCAM 模型目录。
2. 解压 GCAM-China-Studio-0.1.1-win-unpacked.zip，将其中 win-unpacked 替换原 GCAM-Studio\release\win-unpacked。不要用空 data 覆盖旧 data。
3. 运行 win-unpacked\GCAM-China Studio.exe。打开“设置与诊断”，确认模型根目录、Rscript、Java 和 Studio 数据目录正确，环境自检通过。
4. 若独立安装或使用单文件 portable，默认数据位于 %APPDATA%\gcam-china-studio\data；要继续旧 Profile，在设置中选择原 GCAM-Studio\data。
5. 先复制待测 Profile 留作备份，启用新版快速验证。CSV 有改动时会自动重建 XML，第一次构建和求解可能需要几十分钟，任务 running 且进程仍在计算时请等待。
6. 快速验证成功只验证到 2025 年。需要 2050/2100 等正式结果时，关闭快速验证并设置目标年，等待该次运行显示 success 后再查询导出。
7. 已有的旧版失败运行保留为诊断记录；更新程序不会把旧失败结果变成成功，需要重新运行。

六、若实际修改的情景仍然失败

先新建未改动的同模板基线，以标准精度运行。如果基线成功而修改情景失败，逐批回退 CSV/政策，定位首次出现失败的改动；重点核对单位、数量级、空值、负值、历史校准年份和政策强度。保持标准求解器，不用放宽阈值掩盖输入问题。

请保留该次运行目录的 manifest.json、configuration.xml、gcam.log、logs 和对应 build.log。Windows 4551 属于系统应用控制拦截，应根据日志中的真实 exe 路径由 IT 处理；磁盘不足、R 包加载失败、Java/JVM 不匹配会由环境诊断或任务日志给出具体原因。

同事本次实际改过的 CSV 尚未提供，因此尚未复现那一份特定情景。以上真实验收证明软件链路及所列两种情景通过；任意新政策或数据能否数学收敛，仍以其完整运行的收敛、校准和结果检查为准。
