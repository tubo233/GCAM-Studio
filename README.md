# GCAM-China Studio

GCAM-China v8 的情景与数据工作台：编辑 CSV → 用 R 生成 XML → 调用 GCAM 求解 → 查询与导出结果。当前版本 **0.1.4**。

## 解压覆盖更新

给同事使用 `GCAM-China-Studio-0.1.4-source.zip`。退出旧的启动窗口，把压缩包中的 `GCAM-Studio` 内容解压到原来的同名目录，选择覆盖源码文件，然后双击唯一的 **启动.bat**。

更新包包含源码和与之匹配的网页文件，不包含 `data`、`runtime`、`node_modules`、模型数据、个人设置或 `release`。因此不会覆盖已有 Profile、CSV/XML 覆盖、历史结果、Python/R 环境和本机设置。更新前可以自行备份 `data`；不要先删除原目录。第一次运行新版入口会清理已知的旧版 `启动 GCAM Studio.bat` 和旧故障说明文件。

`启动.bat` 直接运行 Python 源码服务并打开浏览器，默认地址为 **http://127.0.0.1:8765**，不调用 `release` 里的 exe，也不启动 Electron。保留启动窗口；按 Ctrl+C 停止。

启动窗口第一行应显示 `[源码启动器] GCAM-China Studio 0.1.4`。若仍出现旧版“前端构建失败，请查看上面的 npm 输出”，请确认覆盖的是原目录中的 `启动.bat`，不要解压成多嵌套一层的目录。新版构建直接调用本地 TypeScript/Vite 文件，兼容复制依赖后缺少 `.bin/tsc.cmd` 的情况；LF/CRLF 换行变化不会触发无意义的重建。

## 启动时检查 GitHub 更新

正常启动会检查 `tubo233/GCAM-Studio` 的 `main` 分支。从 0.1.4 起，有版本记录的源码解压版和 Git 克隆版会自动安装可用更新；没有版本记录时仍需确认。0.1.3 用户升级到本版时，旧启动器会最后询问一次，输入 `y` 即可。请等正在运行的任务结束后再关闭启动窗口，重新双击 `启动.bat`；刷新网页不等于重启。网络失败继续使用本地版本；`启动.bat -SkipUpdate` 跳过本次检查，`-CheckOnly` 只检查运行环境。旧的独立 exe 不走此更新流程。

更新按检查时的固定提交下载。程序先校验源码、网页文件并备份，成功后自动重新启动一次；中途失败会恢复旧源码，下次启动也会恢复上次被中断的更新。备份在 `runtime/updates`。仅更新程序文件，保留 `data`、本机配置、模型目录、Python/R 环境及 `release`。同一源码目录同时只允许一个启动窗口，避免运行中更新。

解压版不要求安装 Git，使用随包记录的提交号检查更新。Git 克隆版要求当前分支为 `main`、没有未提交的源码修改且能够快进；否则保留本地版本，提示先处理源码修改。自动更新通过快进同步 Git 提交和索引，保留未跟踪的私人文件；重名冲突会停止更新。

远端源码附带已校验的网页更新包，因此正常更新无需 Node.js。远端网页包不完整或与源码不一致时，继续使用本地版本，不会先覆盖源码再卡在构建环节。

## 首次运行需要什么

- **64 位 Python 3.11+**。入口优先复用原有可用环境；不可用时在 `runtime/venv-source` 创建本机环境并自动安装后端依赖，不改写旧虚拟环境。
- **GCAM-China v8 模型、64 位 JDK 21 和 R 4.4.x**。在“设置与诊断”中选择本机路径。Rscript 已配置时，入口检查并自动补装所需 R 包；第一次在界面配置 R 后重新启动一次即可。
- 更新包已经附带网页文件，日常运行不需要 Node.js。只有网页源码变化、网页文件缺失，或直接从 GitHub 克隆源码时，才需要 **Node.js 20.19+ 或22.12+**；入口会自动安装 npm 依赖并重新生成网页。

所有依赖下载先使用本地代理 `http://127.0.0.1:1080`。当前下载操作连续失败三次后，会明确提示并改用直连。安装依赖及源码服务均不要求管理员权限。

端口被占用时先退出旧启动窗口。需要其他端口可运行 `启动.bat -Port 8876`；只检查并准备环境可运行 `启动.bat -CheckOnly`；不自动打开浏览器可加 `-NoBrowser`。

## 数据和设置

源码版默认使用当前目录下的 `data`，其中 `settings.json` 保存本机工具与数据目录设置。覆盖更新包不包含该文件。以前已经把数据迁移到其他位置时，会继续读取原设置指定的目录。模型根目录应选择包含 `exe`、`input`、`output` 的那一层，不要选择 `exe` 子目录；Studio 数据目录与模型目录分别设置。

保留每个 Profile 的覆盖输入，基线 CSV 不改写。没有 CSV 改动时复用模型基线 XML；修改、恢复或删除 CSV 覆盖后自动重新选择或构建 XML。首次完整 R 构建可能需要几十分钟，并占用数 GB 磁盘。

源码服务默认也支持局域网访问。只有本机浏览器可以修改关键设置；同事访问地址以启动窗口显示的局域网地址为准。

## 运行与结果

先确认环境检查通过，再选择或新建 Profile 并运行。快速验证保留标准求解精度，只计算至 2025 年或更早；正式计算请关闭快速验证，选择目标年。

运行成功要求退出码 0、所有计算期收敛、校准检查通过且生成有效 BaseX 数据库。失败和取消保留日志与运行历史。查询只导出实际求解的年份，支持 2100 年；快速验证不能代替完整目标年的正式结果。运行或排队期间会锁定相关输入，避免途中改动影响结果。

在“模型配置 → 情景与政策”可载入手工主配置、切换 SSP 模板、勾选政策，并直接按地区和年份编辑约束或碳价。也可切到 XML 源码自由编辑。“输入数据 CSV”使用同一 Profile。保存后前往运行中心可查看实际采用的社会经济输入、政策和目标文件。选择“重新生成 XML”可显式用当前 CSV 运行 R 构建。

若出现“政策目标搜索失败”，即使各年份均已求解、结果库已生成，也不表示政策目标已达到。请查看本次运行目录的 `logs/target_finder_log.txt`、`configuration.xml` 和对应政策目标文件；不要仅据此认定迭代上限过低。

## 开发、测试与自行编译 exe

源码运行和 exe 编译相互独立。若需要自行编译，可让 agent 在源码目录安装开发依赖并执行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/setup-runtime.ps1
npm run build
```

`setup-runtime.ps1` 安装开发用 Python、npm 和 R 依赖，下载同样遵循代理三次失败后直连的规则。编译产物写入本机 `release`，不上传到源码仓库；覆盖更新也不会改动本机已有 `release`。

```powershell
npm run test:backend
npm run build:web
```

仓库包含后端回归测试。0.1.1 已通过真实标准 SSP2 基线至 2100 年、隔离 Profile 修改 CSV 后生成 304 个 XML 并标准求解至 2025 年、结果查询、离线 XML 编辑及跨 Profile 保存验收。

## 发布后续更新

修复源码后先运行 `npm run build:web`。该命令同时生成 `distribution/web.zip` 与校验清单，把这两个文件和源码一起提交到 GitHub `main`，使用新版源码启动器的电脑会在下次正常启动时自动更新。最后运行 `runtime/venv/Scripts/python.exe tools/package_source.py` 生成覆盖包，包内自动记录当前提交号。`distribution/web.zip` 只包含网页资源，不包含 exe。
